# Easyvet V1 — capacidades y rutas

Este archivo es la matriz compacta vigente de módulos, rutas y alcance. Las rutas contextuales clínicas se renderizan dentro del AppShell y requieren sesión, tenant y permiso de API. `/health` es una página técnica autenticada; el health check de API es `GET /api/v1/health`.

| Capacidad                             | Estado                      | Rutas SPA vigentes / límites                                                                                                                                                                          |
| ------------------------------------- | --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Autenticación y acceso                | READY                       | `/login`, `/cambiar-contrasena`, `/seleccionar-organizacion`, `/acceso-denegado`; el cambio obligatorio bloquea AppShell.                                                                             |
| Dashboard                             | READY                       | `/dashboard`; agregados reales limitados por permiso.                                                                                                                                                 |
| Owners / Patients                     | READY                       | `/propietarios`, `/propietarios/nuevo`, `/propietarios/:ownerId`, `/propietarios/:ownerId/editar`; `/pacientes`, `/pacientes/nuevo`, `/pacientes/:patientId`, `/pacientes/:patientId/editar`.         |
| Agenda                                | READY                       | `/agenda`, `/agenda/nueva`, `/agenda/citas/:appointmentId`, `.../editar`, `.../reprogramar`; disponibilidad en `/agenda/disponibilidad`, `/nueva`, `/:ruleId/editar`.                                 |
| Clínica                               | READY WITH KNOWN LIMITATION | Contexto `/pacientes/:patientId/historia`: `/nueva`, `/encuentros/:encounterId`, `/editar`, `/evoluciones/nueva` y `.../evoluciones/nueva`.                                                           |
| Prescriptions                         | READY                       | `.../prescripciones`, `.../prescripciones/:prescriptionId`, `.../editar`, y `.../encuentros/:encounterId/prescripciones/nueva`.                                                                       |
| Preventive Care                       | READY                       | `.../preventivos`; `.../preventivos/vacunas/:vaccinationId` y `.../desparasitaciones/:dewormingId`; altas/ediciones bajo el encuentro contextual.                                                     |
| Procedures / Surgery / Anesthesia     | READY                       | `.../procedimientos`, `.../procedimientos/:procedureId`, `.../editar`, nueva por encuentro; `.../anestesias/:anesthesiaRecordId`, nueva por encuentro y edición.                                      |
| Hospitalization / Diagnostics         | READY                       | `.../hospitalizaciones`, `.../hospitalizaciones/:hospitalizationId`, `.../editar`, nueva por encuentro; `.../diagnosticos`, `.../diagnosticos/:diagnosticOrderId`, `.../editar`, nueva por encuentro. |
| Documents / Consents / Signatures     | READY WITH KNOWN LIMITATION | `.../documentos`; `.../consentimientos`, detalle/edición y alta por encuentro; `/firmar/:token` es público, aislado del AppShell. Integración remota S3/email no live-test.                           |
| Follow-ups                            | READY                       | `/seguimientos`, `/:followUpId`, `/:followUpId/editar`; alta contextual `.../seguimientos/nuevo`. Recordatorios son internos.                                                                         |
| Grooming                              | READY                       | `/peluqueria`, `/peluqueria/nueva`, `/:groomingVisitId`, `/editar`.                                                                                                                                   |
| Inventory                             | READY WITH KNOWN LIMITATION | `/inventario`, `/inventario/nuevo`, `/:itemId`, `/editar`; sin compras/proveedores.                                                                                                                   |
| Sales / Billing / Cash                | READY WITH KNOWN LIMITATION | `/ventas`, `/ventas/nueva`, `/:saleId`, `/editar`; `/facturacion`, `/:invoiceId`; `/caja`. Factura interna, sin proveedor fiscal/pago.                                                                |
| Users / Settings / Reports            | READY                       | `/usuarios`, `/usuarios/nuevo`, `/:membershipId`; `/configuracion`; `/informes`; `/perfil/profesional`.                                                                                               |
| Health / 404                          | READY                       | `/health` (liveness) y `/api/v1/health/ready` (base de datos); cualquier ruta desconocida produce una página Not Found, no un placeholder.                                                         |
| Integraciones externas / móvil nativo | NOT INCLUDED V1             | Email/SMS/push, Google Calendar, laboratorios externos, fiscalidad/pasarela, app nativa/offline y exportaciones avanzadas.                                                                            |

El build carga dominios principales con imports lazy. Navegación global filtrada por permiso; una URL manual no sustituye la autorización de la API. El estado global de la release, evidencias y gaps manuales están en [QA de cierre](../qa/v1-closure.md). La etiqueta READY describe alcance implementado y cubierto por sus suites, no certificación de producción.
